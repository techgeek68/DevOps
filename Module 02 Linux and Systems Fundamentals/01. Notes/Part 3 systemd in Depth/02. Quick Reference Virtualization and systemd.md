## Quick Reference: Virtualization and systemd

| Concept | What It Is | Why It Matters |
|---|---|---|
| Type 1 hypervisor | Direct hardware access, no host OS | Used in every cloud provider and production data center |
| Type 2 hypervisor | Runs on top of a host OS | Correct choice for local lab and development environments |
| Container isolation | Process namespace, shared host kernel | Fast and lightweight but weaker security boundary than a VM |
| KVM | Linux kernel becomes a Type 1 hypervisor when the module loads | The dominant hypervisor in Linux based production infrastructure |
| systemd unit | A configuration file describing one manageable entity | Everything systemd manages is a unit |
| `.service` | A unit for a daemon or long running process | The unit type you write and manage most frequently |
| `.timer` | A unit for scheduled execution | The modern replacement for cron |
| `After=` | Ordering without hard dependency | Service starts after, but does not require, the listed unit |
| `Requires=` | Hard dependency | Service fails to start if the listed unit fails |
| `Restart=on-failure` | Auto restart on nonzero exit or crash | Essential for production daemons |
| `multi-user.target` | Fully booted server state, no GUI | The standard default target for headless servers |
| journald | systemd's binary, structured logging subsystem | Centralized logs for every service with microsecond timestamps |
| `journalctl -u <unit> -f` | Follow logs for one unit in real time | The first command you run when a service is misbehaving |
| Socket activation | Service starts on first connection, not at boot | Demand driven startup, connection buffering during restarts |
