## 12. Viewing and Managing Logs

`Viewing and Managing Logs` in Linux involves accessing, filtering, and maintaining log files to monitor system activity, diagnose issues, and audit events. Logs are essential for troubleshooting and maintaining system health.

`journalctl` is the primary tool for querying the systemd journal, with `-u` filtering by service, `-f` following logs in real time, `--since` and `--until` filtering by time range, and `-p` filtering by priority level. Traditional log files are stored in `/var/log/`, with common files including `syslog`, `auth.log`, `kern.log`, and `dmesg`. `tail -f` follows a log file in real time, and `grep` filters log output for specific patterns. `logrotate` manages log file rotation, compression, and deletion to prevent logs from consuming excessive disk space. `dmesg` displays kernel ring buffer messages, useful for diagnosing hardware and boot issues.

**`journalctl` for systemd journals:**

`journalctl` is the command-line tool for querying and displaying logs collected by the systemd journal. It provides powerful filtering and formatting options for inspecting system and service activity.

`journalctl -u servicename` filters logs for a specific service, and `-f` follows the journal in real time. `--since` and `--until` accept timestamps such as `"2026-01-01 00:00:00"` or relative values like `"1 hour ago"` to filter by time range. `-p` filters by priority level, accepting values such as `emerg`, `alert`, `crit`, `err`, `warning`, `notice`, `info`, and `debug`. `-b` shows logs from the current boot, and `-b -1` shows logs from the previous boot. `-n` limits output to a specified number of lines. `-o json` and `-o short` control output format. `--disk-usage` reports the total disk space consumed by the journal, and `--vacuum-size` and `--vacuum-time` remove old journal entries to free space.

- Basic viewing
```bash
journalctl                                            # all logs oldest first
```
```bash
journalctl -f                                         # follow new entries in real time (like tail -f)
```
- Filter by service
```bash
journalctl -u nginx.service                           # logs for nginx only
```
```bash
journalctl -u sshd --since "1 hour ago"               # sshd logs from last hour
```

**Log rotation with `logrotate`:**

`Log rotation with logrotate` is the process of automatically managing log file size and age by rotating, compressing, and deleting old log files. It prevents logs from consuming excessive disk space and keeps the filesystem organized.

`logrotate` is configured through `/etc/logrotate.conf` for global settings and `/etc/logrotate.d/` for application-specific configuration files. Key directives include `daily`, `weekly`, and `monthly` to set the rotation frequency, and `rotate` to specify how many old copies to retain. `compress` enables gzip compression of rotated logs, and `delaycompress` postpones compression until the next rotation cycle. `missingok` suppresses errors if a log file is absent, and `notifempty` skips rotation if the log file is empty. `postrotate` and `endscript` define commands to run after rotation, such as reloading a service. `logrotate -d` runs in debug mode to test a configuration without making changes.

**Config locations**
```
/etc/logrotate.conf          # global defaults
/etc/logrotate.d/            # per-service configs (nginx, apache, etc.)
```

- `/etc/logrotate.d/nginx`
```bash
/var/log/nginx/*.log {       # apply to all .log files in nginx folder
    daily                    # rotate every day
    missingok                # no error if log file is missing
    rotate 7                 # keep last 7 copies
    compress                 # gzip old logs
    delaycompress            # compress previous log, not the just-rotated one
    notifempty               # skip if log is empty
    create 0640 nginx adm    # create new empty log (permissions, owner, group)
    sharedscripts            # run postrotate script once for all logs
    postrotate
        systemctl reload nginx    # reload nginx, so it writes to the new log file
    endscript
}
```
- Commands:
```bash
sudo logrotate -vf /etc/logrotate.d/nginx     # force rotate right now (verbose)
```
```bash
sudo logrotate -d /etc/logrotate.d/nginx      # dry run: shows what would happen
```
```bash
sudo cat /var/lib/logrotate/logrotate.status  # check when last rotation ran
```
---
**Expected Output:**

- After rotation, your log folder looks like:
```
/var/log/nginx/access.log          # new empty file
/var/log/nginx/access.log.1        # yesterday's log
/var/log/nginx/access.log.2.gz     # compressed older log
/var/log/nginx/access.log.3.gz     # even older
```
---
> **Why does `postrotate` reload nginx?**
> 
> After rotation, the old log file is renamed, but nginx still writes to it by file handle. Reloading nginx makes it open the new empty file instead.

> **`delaycompress`**
> 
> The most recent rotated log stays uncompressed so you can read it easily without gunzip. Only older ones get compressed.
