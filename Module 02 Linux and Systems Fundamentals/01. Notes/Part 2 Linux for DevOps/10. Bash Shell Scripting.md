## 10. Bash Shell Scripting

`Bash Shell Scripting` refers to writing scripts using the Bash shell to automate tasks, execute sequences of commands, and manage system operations. Scripts are plain text files containing shell commands that are executed sequentially.

Scripts begin with a shebang line `#!/bin/bash` that tells the system which interpreter to use. Variables are defined without spaces around the `=` sign and referenced with `$`. `if` statements handle conditional logic, `for` and `while` loops iterate over values or conditions, and `case` statements handle multiple branching options. `$1`, `$2`, and `$@` represent positional parameters passed to the script. `chmod +x` makes a script executable, and scripts are run with `./scriptname.sh` or by specifying the full path.

---
### Terminal vs Shell

| Component | Function | Examples |
|---|---|---|
| Shell | Executes commands and scripts | bash, zsh, sh, fish |
| Terminal emulator | Hosts the shell and handles display | GNOME Terminal, xterm, iTerm2 |

Bash (Bourne Again Shell) is the default shell on most Linux distributions and the standard for DevOps scripting.

### Variables

`Variables` in Bash store data that can be referenced and manipulated throughout a script or shell session. They are fundamental to writing dynamic and reusable scripts.

Variables are defined without spaces around the `=` sign, such as `name="Linux"`, and referenced using `$name` or `${name}`. Environment variables are available system-wide and set using `export`, such as `export PATH`. `$HOME`, `$USER`, `$SHELL`, and `$PATH` are common built-in environment variables. `$?` holds the exit status of the last command, `$$` holds the current process ID, and `$#` holds the number of arguments passed to a script. `unset` removes a variable, and `readonly` makes a variable immutable.

### String Manipulation

Bash has built-in string operations you can use directly without calling external tools. These are faster and keep your scripts cleaner.

---
**String length:**
```bash
name="devops"
```
```bash
echo ${#name}            # Output: 6
```
---
**Substring extraction:**
```bash
echo ${name:0:3}         # Output: dev (start at index 0, take 3 chars)
```
```bash
echo ${name:3}           # Output: ops (from index 3 to end)
```
---
**Remove prefix/suffix:**
```bash
file="backup-2026-06-01.tar.gz"
```
```bash
echo ${file%.tar.gz}                   # Remove suffix: backup-2026-06-01
```
```bash
echo ${file#backup-}                   # Remove prefix: 2026-06-01.tar.gz
```
---
**Replace substring:**
```bash
path="/home/user/logs"
```
```bash
echo ${path/user/admin}   # Replace first match: /home/admin/logs
```
```bash
echo ${path//o/0}         # Replace all matches: /h0me/user/l0gs
```
---
**Convert case:**
```bash
str="Hello World"
```
```bash
echo ${str,,}             # all lowercase: hello world
```
```bash
echo ${str^^}             # all uppercase: HELLO WORLD
```
---
**Default values:**
```bash
echo ${MY_VAR:-"default"}      # Use default if MY_VAR is unset or empty
```
```bash
echo ${MY_VAR:="default"}      # Set and use default if MY_VAR is unset
```
---
> String manipulation with `${}` is much faster than calling `sed` or `awk` for simple cases inside loops.

### Arrays

`Arrays` in Bash store multiple values under a single variable name.

---
**Indexed arrays:**
```bash
servers=("web01" "web02" "db01" "db02")
```
```bash
echo ${servers[0]}            # First element: web01
```
```bash
echo ${servers[@]}            # All elements
```
```bash

```

- Add an element
```bash
servers+=("cache01")
```
- Loop over array
```bash
for server in "${servers[@]}"; do
  echo "Checking: $server"
done
```
---
---
**Associative arrays (key value pairs):**
```bash
declare -A config
config["host"]="192.168.1.10"
config["port"]="8080"
config["env"]="production"

echo ${config["host"]}        # 192.168.1.10
echo ${!config[@]}            # All keys: host port env
echo ${config[@]}             # All values
```
---
> Always quote `"${array[@]}"` when iterating. Without quotes, elements with spaces are split into multiple items.

### Data Types

`Data Types` in Bash are loosely defined, as Bash treats all variables as strings by default. Understanding how Bash handles different types of data is essential for writing accurate and reliable scripts.

Integers can be handled using arithmetic context `$(( ))` or the `let` command for mathematical operations. `bc` is used for floating-point calculations, as Bash does not natively support decimal arithmetic. Arrays store multiple values in a single variable, defined as `array=(value1 value2 value3)` and accessed with `${array[index]}`. Associative arrays use string keys instead of numeric indices and are declared with `declare -A`. `declare` can also enforce integer type with `-i` or read only status with `-r`.

```bash
a=5
b=3
```
```bash
sum=$((a + b))
echo $sum
```
```bash
let "result = a * b"
echo $result
```
>The let command in Linux is used for integer arithmetic operations and variable calculations in shell scripts.

### Operators

`Operators` in Bash are symbols or keywords used to perform arithmetic, comparison, logical, and string operations within scripts and commands.

Arithmetic operators include `+`, `-`, `*`, `/`, and `%` for modulo, used within `$(( ))` context. Comparison operators for integers include `-eq`, `-ne`, `-lt`, `-le`, `-gt`, and `-ge`, used within `[ ]` or `[[ ]]`. String comparison operators include `=` and `!=` for equality, and `-z` and `-n` to test for empty or non-empty strings. Logical operators include `&&` for AND, `||` for OR, and `!` for NOT. File test operators such as `-f`, `-d`, `-e`, and `-r` check whether a file exists, is a directory, or is readable.

---
**Arithmetic:** `+`, `-`, `*`, `/`, `%`, `**`, `++`, `--`

### Control Structures

`Control Structures` in Bash direct the flow of script execution based on conditions, iterations, and branching logic. They are essential for writing scripts that respond dynamically to different inputs and system states.

`if`, `elif`, and `else` handle conditional branching, executing blocks of code based on whether a condition evaluates to true or false. `for` loops iterate over a list of values or a range, and `while` loops repeat a block as long as a condition remains true. `until` loops run until a condition becomes true. `case` statements provide multi way branching based on pattern matching, serving as a cleaner alternative to nested `if` statements. `break` exits a loop early and `continue` skips the current iteration and proceeds to the next.

---
**if / elif / else:**

```bash
read -p "Enter your age: " age
if [ $age -ge 18 ]; then
  echo "Adult"
elif [ $age -ge 13 ]; then
  echo "Teenager"
else
  echo "Child"
fi
```

**case statement:**

`case` statement in Bash provides multi way branching by matching a variable or expression against a series of patterns. It is a cleaner and more readable alternative to nested `if-elif` chains when handling multiple possible values.

A `case` statement begins with `case variable in`, followed by pattern blocks ending with `;;`, and closes with `esac`. Patterns can include wildcards such as `*` to match any value, and `|` to match multiple patterns in a single block. The `*)` pattern serves as a default catch all, similar to `else` in an `if` statement. `case` is commonly used for handling command line arguments, menu selections, and string matching in scripts.

---
**Example:** Case statement in Bash
```bash
case $1 in
  start)
    echo "Starting service..."
    ;;
  stop)
    echo "Stopping service..."
    ;;
  restart)
    echo "Restarting service..."
    ;;
  *)
    echo "Usage: $0 {start|stop|restart}"
    ;;
esac
```

### Loops

`Loops` in Bash repeatedly execute a block of commands based on a condition or over a set of values. They are essential for automating repetitive tasks and processing lists of items in scripts.

`for` loops iterate over a list of values or a numeric range using `{start..end}` syntax. `while` loops execute as long as a condition remains true, and `until` loops run until a condition becomes true. `break` exits a loop immediately and `continue` skips the current iteration and moves to the next. `select` is a special loop used to generate simple interactive menus from a list of options. Loops can be nested, and output from a loop can be piped or redirected like any other command.

---

---
**Example 4:** Iterate over an array

### Functions

`Functions` in Bash are named blocks of reusable code that can be called multiple times within a script. They improve readability, reduce repetition, and allow scripts to be organized into logical sections.

Functions are defined using `function_name() { }` or the `function` keyword followed by the function name. Arguments are accessed inside a function using `$1`, `$2`, and `$@`, independent of the script's own positional parameters. `return` exits a function and optionally passes a numeric exit status, accessible via `$?`. Variables declared with `local` are scoped to the function and do not affect the global environment. Functions must be defined before they are called in a script and can be exported to subshells using `export -f`.

### Heredoc

`Heredoc` (here document) is a way to pass a block of text to a command or write it to a file without opening an editor. You have already seen it used with `cat` to create files.

The `EOF` marker tells Bash where the text block starts and ends. The name `EOF` is just a convention; you can use any word as the marker.

---
**Write a multi line file:**
```bash
cat > ~/newfile << 'EOF'
Welcome to the DevOps server.
Unauthorized access is prohibited.
Contact: admin@company.com
EOF
```

### Debugging

`Debugging` in Bash involves identifying and resolving errors in scripts to ensure they execute correctly and predictably. It is essential for diagnosing unexpected behavior, logic errors, and syntax mistakes.

`set -x` enables trace mode, printing each command and its arguments as they are executed. 

`set -e` causes the script to exit immediately if any command returns a non zero exit status. 

`set -u` treats unset variables as errors, preventing silent failures from undefined variables. 

`set -o pipefail` ensures that a pipeline returns a non-zero status if any command within it fails. These options can be combined as `set -euxo pipefail` at the top of a script for strict error handling. `bash -n` checks a script for syntax errors without executing it, and `bash -v` prints each line as it is read.

---
- Run the entire script with tracing
```bash
bash -x backup.sh            # trace every command as it executes
```

### Exit Status

`Exit Status` in Bash is a numeric value returned by a command or script upon completion, indicating whether it succeeded or failed. It is fundamental to error handling and conditional logic in shell scripting.

A value of `0` indicates success, while any non-zero value indicates failure. `$?` holds the exit status of the most recently executed command. `exit` terminates a script and optionally returns a specific exit status code. `true` always returns `0` and `false` always returns `1`, useful in loops and conditionals. Exit statuses can be tested using `if`, `&&`, and `||` to control script flow based on command outcomes. By convention, exit codes between `1` and `255` represent different categories of errors, with `127` indicating a command not found and `128` indicating an invalid exit argument.

---
`$?`: holds the exit code of the last command

---
- Examples:
  
```bash
ls /tmp
```
```
echo $?
```
```bash
ls /no/such/path
```
```
echo $?
```
> Rule:`0` = Successful execution of command, anything else = failure
---

**-Example:** `exit` in a script, return status to the caller

```bash
#!/usr/bin/env bash
if [ ! -f "$1" ]; then        # if file does NOT exist
  echo "File not found" >&2   # print error to stderr (not stdout)
  exit 1                      # exit with failure
fi
echo "File exists"
exit 0                        # exit with success
```
- Running it:
```bash
./exit.sh /etc/passwd
```
```bash
echo $?
```
```bash
./exit.sh /etc/password
```
```bash
echo $?
```

### Error Handling with `trap`

`trap` catches signals and errors in a script so you can clean up or log something before the script exits unexpectedly. This is important for scripts that create temporary files, hold locks, or make system changes that need to be rolled back on failure.

**Cleanup on exit:**
```bash
#!/bin/bash
TMPFILE=$(mktemp)

cleanup() {
  echo "Cleaning up temp file..."
  rm -f "$TMPFILE"
}

trap cleanup EXIT           # Run cleanup() on any exit

echo "Working with $TMPFILE"
# ... do something ...
```

**Catch errors:**
```bash
#!/bin/bash
set -e

trap 'echo "Error on line $LINENO. Exit code: $?"' ERR

cp /etc/passwd /tmp/passwd_backup
echo "Backup succeeded"
```
---
**Common trap signals:**

| Signal | When it fires |
|---|---|
| `EXIT` | Script exits for any reason |
| `ERR` | Any command returns non-zero |
| `INT` | User presses Ctrl+C |
| `TERM` | Script receives kill signal |

---
> `trap` with `EXIT` is the most practical pattern. It guarantees cleanup happens whether the script finishes normally, hits an error, or is killed.

### Practical Script Template

This is the recommended starting structure for production scripts. It handles common edge cases that catch beginners off guard.

```bash
#!/bin/bash
set -euo pipefail                         # Exit on error, undefined var, pipe failure

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"  # Directory where this script lives
LOGFILE="/var/log/myscript.log"

log() {
  echo "[$(date '+%Y-%m-%d %H:%M:%S')] $*" | tee -a "$LOGFILE"
}

cleanup() {
  log "Script exiting."
}
trap cleanup EXIT

if [[ $# -lt 1 ]]; then
  echo "Usage: $0 <argument>" >&2
  exit 1
fi

log "Starting with argument: $1"
# ... rest of script ...
```

---
> `set -euo pipefail` at the top is the single most important habit. It prevents scripts from silently continuing after failures.
